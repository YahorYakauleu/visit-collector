# Visit collector — сборщик визитов на пейволл

Отдельный лёгкий сервис для воронки «Визит → Триал» в Billing Dashboard. Лендинг сообщает о каждом показе пейволла, сборщик считает посетителей и визиты по дням и разрезам. Визиты поштучно не хранятся — только счётчики, поэтому сервис держит миллионы визитов в сутки на самом маленьком сервере.

## Как работает

1. **Лендинг** при показе пейволла отправляет визит: сайт и первый ли это визит посетителя (браузер знает это сам — у него ещё не было id). По желанию — источник, кампания, A/B-тест и сегмент, вариант пейволла.
2. **Сборщик** не пишет визит на диск, а прибавляет его к счётчику «сутки × сайт × источник × кампания × A/B × вариант × страна × устройство × ОС». Раз в минуту все счётчики уходят в базу одной пачкой.
3. **Триал.** Когда посетитель оформил подписку, лендинг сообщает об этом вместе со временем первого визита. Триал прибавляется к суткам первого визита (когорта: «из посетителей 14.10 оформили N») — если оформлен не позже чем через 7 дней, — и к суткам оформления, для сверки с платёжными провайдерами.
4. **Дашборд** забирает посетителей, визиты и триалы по дням (`/api/stats`) и считает «Визит → Триал».

Страна — по IP (заголовок `CF-IPCountry` от Cloudflare), сам IP не хранится. Устройство и ОС — по User-Agent. Известные боты и запросы без User-Agent считаются отдельно (`bots`) и в посетителей не входят.

## API

### `POST /v1/visit` — визит с лендинга

Тело — JSON, отправленный как `text/plain` (так `sendBeacon` не делает CORS-preflight). Ответ — `204`.

| Поле | |
|---|---|
| `first` | `true` — первый визит посетителя (у браузера ещё не было id) |
| `site` | домен лендинга (`location.host`); можно полным адресом — останется только домен. Без него — домен из заголовка `Origin` |
| `source` | UTM source |
| `campaign` | id или название кампании |
| `ab_test`, `ab_segment` | A/B-тест и сегмент |
| `variant` | вариант пейволла |

Все поля необязательные; строки длиннее 64 символов обрезаются. Пример для лендинга:

```js
const first = !localStorage.getItem('tg_visitor_id');
if (first) localStorage.setItem('tg_visitor_id', crypto.randomUUID());
navigator.sendBeacon(
  'https://<домен сборщика>/v1/visit',
  JSON.stringify({ first, site: location.host }),
);
```

**Триал** — тот же адрес, тело `{ "event": "trial", "site": "<домен>", "first_visit": "<ISO-время первого визита>" }`. Лендинг отправляет его один раз на браузер. Без `first_visit`, со временем из будущего или старше 7 дней триал считается только в сутки оформления.

Ответы: `204` — принят; `400` — не JSON; `403` — чужой домен (`ALLOWED_ORIGINS`); `413` — больше 2 КБ; `429` — больше `RATE_LIMIT_PER_MINUTE` визитов с одного IP в минуту.

### `GET /api/stats` — цифры для дашборда

Заголовок `Authorization: Bearer <READ_TOKEN>`.

`?from=YYYY-MM-DD&to=YYYY-MM-DD&group=source&country=US&country=SA`

- `group` — разрез: `site`, `source`, `campaign`, `ab_test`, `ab_segment`, `variant`, `country`, `device`, `os`; без него — только по дням.
- Фильтры — те же имена; несколько значений одного фильтра — через ИЛИ; `none` — не определено.
- Ответ: `{ from, to, time_zone, group, rows: [{ day, value, visitors, visits, bots, trials, trials_started }] }`. `visitors` — первые визиты, `visits` — все показы пейволла, `trials` — триалы посетителей, впервые пришедших в эти сутки, `trials_started` — триалы, оформленные в эти сутки.

### `GET /health` — без авторизации, `ok`.

## Настройки

Как в [.env.example](.env.example): `READ_TOKEN` (обязательно), `ALLOWED_ORIGINS`, `TIMEZONE` (по умолчанию America/New_York — как у Stripe в дашборде), `FLUSH_SECONDS` (60), `RATE_LIMIT_PER_MINUTE` (60), `DATA_DIR`, `PORT`.

## Нагрузка

Ориентир — миллионы визитов в сутки: это десятки визитов в секунду в среднем и несколько сотен в пике.

Docker с ограничением как у Render Starter (0,5 CPU, 512 МБ), `npm run loadtest`:

| Режим | Принято в секунду | Задержка p50 / p99 | Ошибки |
|---|---|---|---|
| Ровно 400/с (пик) | 400 | 0,6 / 1,9 мс | нет |
| Ровно 1 200/с (тройной запас) | 1 199 | 0,5 / 4,3 мс | нет |
| Максимум, 100 соединений | ~15 900 | 2,2 / 62 мс | нет |

Память под нагрузкой — около 110 МБ. Сумма визитов в отчёте совпала с числом принятых тестом до единицы.

```bash
npm run loadtest -- --url http://127.0.0.1:3000 --rate 400 --seconds 30
```

Не запускать против продового сборщика — визиты попадут в счётчики.

## Деплой (Render)

- Docker, отдельный сервис; диск на `/app/data` (1 ГБ хватит надолго — база растёт на число разных сочетаний разрезов в сутки, а не на число визитов).
- Переменные — как в `.env.example`; `READ_TOKEN` — длинная случайная строка, её же получит дашборд.
- Health check — `/health`.
- Свой домен за Cloudflare (с проксированием) — тогда есть страна по IP (`CF-IPCountry`), и запросы на свой домен реже режут блокировщики рекламы.
- Один экземпляр: база — SQLite на диске сервиса. Счётчики за последнюю минуту пишутся на диск и при остановке; визиты, пришедшие во время самого перезапуска (деплой), теряются.
