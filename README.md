# Visit collector — сборщик событий с лендинга

Отдельный лёгкий сервис для воронок в Billing Dashboard. Лендинг сообщает о событиях — пока одно: уникальный посетитель пейволла, — сборщик считает их по дням и разрезам. События поштучно не хранятся — только счётчики, поэтому сервис держит миллионы событий в сутки на самом маленьком сервере.

## Как работает

1. **Лендинг** отправляет событие: имя и сайт. По желанию — источник, кампания, A/B-тест и сегмент, вариант пейволла. Уникальность решает браузер: событие «один раз на браузер» он просто не отправляет повторно.
2. **Сборщик** не пишет событие на диск, а прибавляет его к счётчику «сутки × событие × сайт × источник × кампания × A/B × вариант × страна × устройство × ОС». Раз в минуту все счётчики уходят в базу одной пачкой.
3. **Дашборд** забирает счётчики по дням (`/api/stats`).

Страна — по IP (заголовок `CF-IPCountry` от Cloudflare), сам IP не хранится. Устройство и ОС — по User-Agent. Известные боты и запросы без User-Agent считаются отдельно (`bots`) и в `count` не входят.

**События** — список `EVENTS` в [src/event.ts](src/event.ts); имена не из списка отклоняются, чтобы мусорные имена не раздули базу. Новое событие — строка в этом списке.

| Событие | |
|---|---|
| `visit` | уникальный посетитель пейволла — лендинг отправляет его один раз на браузер |

## API

### `POST /v1/events` — событие с лендинга

Тело — JSON, отправленный как `text/plain` (так `sendBeacon` не делает CORS-preflight). Ответ — `204`.

| Поле | |
|---|---|
| `event` | имя события из `EVENTS` — обязательно |
| `site` | домен лендинга (`location.host`); можно полным адресом — останется только домен. Без него — домен из заголовка `Origin` |
| `source` | UTM source |
| `campaign` | id или название кампании |
| `ab_test`, `ab_segment` | A/B-тест и сегмент |
| `variant` | вариант пейволла |

Поля, кроме `event`, необязательные; строки длиннее 64 символов обрезаются. Пример для лендинга:

```js
navigator.sendBeacon(
  'https://<домен сборщика>/v1/events',
  JSON.stringify({ event: 'visit', site: location.host }),
);
```

Ответы: `204` — принято; `400` — не JSON или имя не из `EVENTS`; `403` — чужой домен (`ALLOWED_ORIGINS`); `413` — больше 2 КБ; `429` — больше `RATE_LIMIT_PER_MINUTE` событий с одного IP в минуту.

### `GET /api/stats` — цифры для дашборда

Заголовок `Authorization: Bearer <READ_TOKEN>`.

`?from=YYYY-MM-DD&to=YYYY-MM-DD&event=visit&group=source&country=US&country=SA`

- `event` — какие события (можно несколько); без него — все.
- `group` — разрез: `site`, `source`, `campaign`, `ab_test`, `ab_segment`, `variant`, `country`, `device`, `os`; без него — только по дням.
- Фильтры — те же имена; несколько значений одного фильтра — через ИЛИ; `none` — не определено.
- Ответ: `{ from, to, time_zone, group, rows: [{ day, event, value, count, bots }] }`.

### `GET /health` — без авторизации, `ok`.

## Настройки

Как в [.env.example](.env.example): `READ_TOKEN` (обязательно), `ALLOWED_ORIGINS`, `TIMEZONE` (по умолчанию America/New_York — как у Stripe в дашборде), `FLUSH_SECONDS` (60), `RATE_LIMIT_PER_MINUTE` (60), `DATA_DIR`, `PORT`.

## Нагрузка

Ориентир — миллионы событий в сутки: это десятки событий в секунду в среднем и несколько сотен в пике.

Docker с ограничением как у Render Starter (0,5 CPU, 512 МБ), `npm run loadtest`:

| Режим | Принято в секунду | Задержка p50 / p99 | Ошибки |
|---|---|---|---|
| Ровно 400/с (пик) | 400 | 0,6 / 1,9 мс | нет |
| Ровно 1 200/с (тройной запас) | 1 199 | 0,5 / 4,3 мс | нет |
| Максимум, 100 соединений | ~15 900 | 2,2 / 62 мс | нет |

Память под нагрузкой — около 110 МБ. Сумма в отчёте совпала с числом принятых тестом до единицы.

```bash
npm run loadtest -- --url http://127.0.0.1:3000 --rate 400 --seconds 30
```

Не запускать против продового сборщика — события попадут в счётчики.

## Деплой (Render)

- Проще всего — Blueprint: New → Blueprint → этот репозиторий. [render.yaml](render.yaml) создаст всё, что ниже.
- Docker, отдельный сервис; диск на `/app/data` (1 ГБ хватит надолго — база растёт на число разных сочетаний разрезов в сутки, а не на число событий).
- Переменные — как в `.env.example`; `READ_TOKEN` — длинная случайная строка (Blueprint генерирует её сам), её же получит дашборд. `PORT` ставит Render.
- Health check — `/health`.
- Свой домен за Cloudflare (с проксированием) — тогда есть страна по IP (`CF-IPCountry`), и запросы на свой домен реже режут блокировщики рекламы.
- Один экземпляр: база — SQLite на диске сервиса. Счётчики за последнюю минуту пишутся на диск и при остановке; события, пришедшие во время самого перезапуска (деплой), теряются.
